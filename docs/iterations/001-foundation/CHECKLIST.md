# Iteration 001 — Foundation Checklist

## Цель

Создать первый рабочий слой цифрового двойника предприятия: организационную
структуру, сотрудников, штатную структуру и объекты эксплуатации.

---

## Организационная структура

- [x] Фиксированная иерархия Учреждение → Филиал → ЖКС → ПУ (`parent_id` +
      триггер `validate_organization_unit_hierarchy`)
- [x] Обязательные реквизиты (наименование, местоположение, адрес,
      координаты, телефон, e-mail, руководитель)
- [x] Backend API: `organization-units` (List/Get/Create/Update)

---

## Сотрудники и штатная структура

- [x] Справочник должностей (`positions`, CRUD)
- [x] Справочник сотрудников (`employees`, CRUD)
- [x] Автогенерация сокращённого ФИО из фамилии и инициалов
- [x] Телефоны и e-mail сотрудников (1:N, не более одного основного —
      частичные уникальные индексы в БД)
- [x] Кадровые назначения (`employee_assignments`), поддержка нескольких
      назначений одного сотрудника (история + текущее)
- [x] Базовая модель штатных единиц (`staff_positions`)

---

## Объекты эксплуатации

- [x] Справочник типов объектов (`object_types`)
- [x] Справочник назначений объектов (`object_purposes`), назначение
      связано с типом объекта (составной FK + фильтр в API)
- [x] Сущность объекта эксплуатации (`operational_objects`)
- [x] Объект эксплуатации может принадлежать только ПУ (триггер
      `validate_operational_object_owner`)

---

## Backend

- [x] Модули: `organization`, `position`, `employee`, `staffposition`,
      `objecttype`, `objectpurpose`, `operationalobject`
- [x] SQL-first, pgx без ORM (ADR-0001)
- [x] Предметные ошибки (нарушение ограничений БД) возвращаются клиенту
      как понятные сообщения (422), а не сырые ошибки Postgres
- [x] `go build`, `go vet`, `gofmt` — чисто

---

## Frontend

- [x] Страницы списков для всех сущностей Foundation (организации,
      должности, сотрудники, штатные единицы, типы/назначения объектов,
      объекты эксплуатации)

---

## Database

- [x] Миграции 000001–000005 применяются на чистой БД без ошибок
- [x] Ключевые бизнес-правила защищены триггерами/ограничениями БД, а не
      только в backend

---

## Completion

- [x] CHECKPOINT_001-001 published
