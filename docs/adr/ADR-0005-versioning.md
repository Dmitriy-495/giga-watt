# ADR-0005 — Versioning Scheme

## Status

Accepted

## Date

2026-08-15

---

## Context

`docs/VERSION.md` содержал значение `0.0.0-bootstrap` с момента Iteration 000
и не обновлялся после завершения Iteration 000 и Iteration 001.

Ни один существующий документ (README, ROADMAP, CHANGELOG, ADR-0003) не
фиксирует явную схему версионирования — только общее утверждение
"Versioning follows project iterations."

Перед Foundation Hardening необходимо зафиксировать схему явно, чтобы
дальнейшие итерации обновляли версию предсказуемо, не изобретая правило
каждый раз заново.

---

## Decision

Версия проекта имеет вид:

```text
MAJOR.MINOR.PATCH-<iteration-slug>
```

- `MAJOR` — остаётся `0`, пока проект не считается production-ready.
- `MINOR` — увеличивается на 1 при завершении каждой очередной предметной
  итерации (Iteration 000, 001, 002, ...). Bootstrap (Iteration 000) — это
  `0.0.x`, Foundation (Iteration 001) — `0.1.x`, и так далее.
- `PATCH` — увеличивается для технических/укрепляющих проходов внутри уже
  завершённой итерации (например, Foundation Hardening — `0.1.1`), не
  добавляющих новую предметную область.
- `<iteration-slug>` — короткое имя текущей завершённой (или укрепляемой)
  итерации из `docs/iterations/<NNN-slug>/`.

Версия обновляется в `docs/VERSION.md` как часть публикации
CHECKPOINT-документа итерации (см. ADR-0003) или как часть отдельного
технического прохода (hardening), если он публикует собственный итог.

---

## Consequences

Положительные:

- версия однозначно указывает, какая предметная итерация завершена;
- не требует отдельной инфраструктуры (semver-тулинга, автоматической
  генерации) — версия проставляется вручную вместе с CHECKPOINT;
- согласуется с уже принятым ADR-0003 (Iteration Memory).

Отрицательные:

- версия не является строгим SemVer (добавлен suffix с именем итерации) —
  это осознанный компромисс в пользу читаемости связи "версия ↔ итерация".

---

## Example

- `0.0.0-bootstrap` — Iteration 000 (Bootstrap) завершена.
- `0.1.0-foundation` — Iteration 001 (Foundation) завершена.
- `0.1.1-foundation` — Foundation Hardening (технический проход внутри
  Iteration 001, без новой предметной области).
- `0.2.0-<slug>` — Iteration 002 завершена.
