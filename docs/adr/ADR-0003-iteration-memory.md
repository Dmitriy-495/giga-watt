# ADR-0003 — Iteration Memory and Checkpoints

## Status

Accepted

## Date

2026-08-07

---

## Context

Giga Watt является долгосрочным проектом развития цифрового двойника предприятия.

При длительной разработке существует риск потери контекста:

- почему были приняты решения;
- что уже сделано;
- какие ограничения существуют;
- с чего необходимо продолжить работу.

История чатов и устные договорённости не могут являться единственным источником знаний проекта.

---

## Decision

Каждая итерация проекта должна иметь собственный жизненный цикл:

1. Планирование.
2. Выполнение задач.
3. Обновление чек-листа.
4. Получение рабочего результата.
5. Создание CHECKPOINT-документа.

---

## Iteration Checklist

Каждая итерация должна содержать чек-лист:

- цели итерации;
- планируемые мероприятия;
- выполненные задачи;
- текущий статус;
- критерии завершения.

---

## CHECKPOINT Document

Каждая завершённая итерация обязана публиковать документ передачи контекста.

CHECKPOINT должен содержать:

- назначение итерации;
- выполненные работы;
- созданные файлы;
- принятые архитектурные решения;
- текущее состояние проекта;
- известные ограничения;
- инструкции для следующего этапа.

---

## Purpose

CHECKPOINT является механизмом передачи знаний между:

- итерациями;
- разработчиками;
- командами;
- будущими участниками проекта.

---

## Consequences

Положительные:

- сохраняется история развития;
- уменьшается потеря контекста;
- упрощается продолжение разработки;
- архитектурные решения остаются понятными.

Отрицательные:

- требуется дисциплина ведения документации;
- каждая итерация требует дополнительного завершения.

---

## Principle

Каждый этап развития Giga Watt должен оставлять после себя воспроизводимый след:

- код;
- документацию;
- архитектурные решения;
- историю изменений;
- checkpoint передачи контекста.
